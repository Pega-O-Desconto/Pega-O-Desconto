# Internationalization

The site ships in Portuguese (source) and English. There is no build step and no runtime library: the HTML keeps the Portuguese text, and English is applied by `landing/js/i18n.js` when the visitor chooses it.

## How a string is translated

Portuguese is written directly in the markup. The element declares which key replaces it:

```html
<h1 data-i18n="hero.title">Desconto na hora de comprar</h1>
<p data-i18n-html="hero.lead">Cupons, ofertas...</p>
<meta name="description" data-i18n-content="meta.desc" content="..." />
<button data-i18n-aria="nav.aria.open" aria-label="Abrir menu">...</button>
<input data-i18n-placeholder="search.placeholder" placeholder="Buscar" />
```

| Attribute | Effect |
| --- | --- |
| `data-i18n` | Replaces the element's text content |
| `data-i18n-html` | Replaces the inner HTML (used for `<span>` highlights and inline links) |
| `data-i18n-content` | Sets the `content` attribute (meta description, Open Graph, Twitter) |
| `data-i18n-aria` | Sets `aria-label` |
| `data-i18n-placeholder` | Sets `placeholder` |

Keys live in the `EN` object in `landing/js/i18n.js`. A missing key falls back to the Portuguese text already in the HTML, which means a forgotten translation degrades gracefully instead of showing a blank space.

## Switching languages

- The header selector calls `window.podSetLang('en' | 'pt')`.
- The choice is persisted in `localStorage` under `pod-lang`.
- `?lang=en` forces a language for that visit and is what the automated checks use.
- After applying a language, the script dispatches `pod:langchange` on `document`; other modules (the deals feed, for example) listen to it and re-render their dynamic text.
- The document `<html lang>` attribute and the page `<title>` are updated as well.

## Adding a language

1. Add the locale code to `SUPPORTED` in `landing/js/i18n.js`.
2. Duplicate the `EN` object as the new dictionary and translate every key. Do not delete keys — `check-i18n.js` asserts parity between the Portuguese markup and the dictionary.
3. Add an option to the language selector in the four pages (`index.html`, `ofertas.html`, `privacidade.html`, `termos.html`).
4. Translate dynamic strings in `landing/js/ofertas.js` (labels, empty state, dates).
5. Run `npm run check:i18n --prefix tools` and review the generated screenshots in `dist/screenshots/i18n/`.

## Rules

- Legal pages are not paraphrased. The privacy policy and the terms must state the same facts in every language; a translation may change tone, never meaning.
- Never translate brand names, store names, URLs or the operator's legal identity.
- Keep text short enough to fit the layout. The i18n check compares wordmark width and menu height on desktop and mobile and fails on overflow.
- Right-to-left languages would need a `dir` switch and mirrored layout; none is supported today.
